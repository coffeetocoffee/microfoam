# Code-size ceilings for the bare-metal device build, enforced by
# cmake/size_gate.cmake. One line per core: <core> <max .text bytes>.
#
# Scope: every source under src/ except mcf_lzma.c and mcf_sodium.c, which are
# opt-in (the LZMA codec pulls in the vendored SDK; the sodium adapter needs a
# host crypto library). The LZMA codec's own size is reported separately in CI.
#
# The ceilings are measured values plus a few percent, not the measured values
# exactly. Two reasons: the CI toolchain is whatever `apt-get install
# gcc-arm-none-eabi` provides on the runner, so its minor version drifts, and a
# minor version change moves code size by a few bytes (16.1.0 vs 16.2.0 differ
# by 2 bytes on Cortex-M0 for this source set). An exact figure would fail on
# that drift while telling you nothing. A real regression - a new code path, a
# larger table, a feature pulled in by accident - is hundreds of bytes to
# kilobytes, which is an order of magnitude above the allowance.
#
# When growth is intended, raise the number here in the same commit that
# caused it, so the diff records the cost.
#
# Ceilings derived from a measurement on 2026-10-02, arm-none-eabi-gcc 16.2.0:
#   cortex-m0 12,386   cortex-m3 11,444   cortex-m4 11,450   cortex-m7 11,446
# Re-measured 2026-10-03 (arm-none-eabi-gcc 16.1.0) after the seek-ordering fix
# removed some dead engine state; the ceilings are upper bounds, so they stand:
#   cortex-m0 12,358   cortex-m3 11,420   cortex-m4 11,426   cortex-m7 11,422
#
# PROVISIONAL, raised 2026-10-15 for the v1.11.0 journal-contract fixes, which
# added code to mcf_session.c (journal erase rounding, the alignment and overlap
# checks in begin(), and the session magic in close()/begin()). These four
# numbers were NOT measured with arm-none-eabi-gcc: the machine the fix was
# written on had no bare-metal ARM toolchain, no usable WSL distro and no
# container runtime. They are derived from the last real measurement above plus
# 400 B per core, chosen because the measured x86 -Os proxy for this change was
# +232 B and Thumb codegen for the new 32-bit integer arithmetic runs larger
# than the proxy suggested. The old ceilings were within 274 B of the measured
# figures, so they could not absorb it.
#
# Re-measure and tighten these once the toolchain is available. For each core,
# from the repository root:
#
#   cmake -DCORE=cortex-m0 -DCC="$(command -v arm-none-eabi-gcc)" \
#         -DSRC="$PWD" -DBASELINE="$PWD/cmake/size_baseline.txt" \
#         -DWORK="$PWD/build-size" -P cmake/size_gate.cmake
#
# That prints the real .text total. Subtract the same few-percent allowance the
# file already describes and write the result back here, so the gate regains the
# margin this provisional raise gave away.
cortex-m0 12800
cortex-m3 11850
cortex-m4 11850
cortex-m7 11850
